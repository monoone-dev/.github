# Security policy

This is the default security policy for every repository of the MonoOne organization that does
not have its own. A repository's own `SECURITY.md` takes precedence over this one.

## Reporting a vulnerability

**Please do not open a public issue, discussion or pull request for a security problem.**

Report it privately through GitHub, for any MonoOne app, website or repository:

1. Open the
   [security advisory form](https://github.com/monoone-dev/index-one-landing-page/security/advisories/new)
   (the **Report a vulnerability** button on the
   [Security tab](https://github.com/monoone-dev/index-one-landing-page/security) of
   `monoone-dev/index-one-landing-page`).
2. Say which product, site or repository the report is about, and describe the issue. Only you and
   the maintainers can see the report.

If the repository you found the problem in shows its own **Report a vulnerability** button, you can
use that instead.

Please include:

- the product and version, and your macOS version where it matters;
- what an attacker can do, and what they need first (local access, a malicious link…);
- steps to reproduce, ideally with a minimal proof of concept;
- whether you have told anyone else.

**Use test data only.** Do not send real personal data, passwords, API keys or tokens, yours or
anyone else's.

## What to expect

- We acknowledge a report within **5 business days**.
- We keep you updated while we investigate, and tell you when a fix ships.
- We credit you in the release notes and the advisory, unless you ask us not to.
- Please give us a reasonable time to release a fix before you disclose publicly. We aim to fix
  critical issues within **30 days**.

We will not take legal action against research done in good faith that follows this policy, avoids
harming users and their data, and stops at proving the issue.

## Supported versions

Security fixes go into the **latest release** only. Please update before reporting, and check whether
the problem still reproduces.
